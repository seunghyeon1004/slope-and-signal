# Slope and Signal

**Be an Earth system trend detective.** A static web app for NASA Space Apps Challenge 2026,
challenge "Be An Earth System Trend Detective!". Team Slope and Signal: Seunghyeon Baek, Kim Mi Yeon.

Live site: https://seunghyeon1004.github.io/slope-and-signal/

Pick a variable (temperature, rain, soil wetness, snow, sunshine and more), a place and a period.
The app fetches NASA POWER monthly data live in your browser (no key, no login), draws the time
series (raw monthly, yearly values, anomalies with the seasonal cycle removed), and tests the trend:

- least-squares slope per decade with a 95% confidence interval and a t-test,
  adjusted for lag-1 autocorrelation with the effective sample size n(1 - r)/(1 + r) (Santer et al. 2000);
- Mann-Kendall test with tie correction, plus the Hamed and Rao (1998) autocorrelation correction
  (first 3 lags; the variance factor is floored at 1 so the correction never makes a test less cautious);
- Theil-Sen slope with the Sen (1968) confidence interval.

It then answers in plain English: what is changing, where, how much, and whether it is statistically
significant (always with the test and p-value). If a trend is not significant, it estimates how many
more years at the same slope and noise would be needed.

## Data

- **NASA POWER** monthly point API, https://power.larc.nasa.gov/ (NASA Langley Research Center), v2.10.
  Meteorology: **MERRA-2** reanalysis (NASA GMAO). Surface radiation and cloud: **GEWEX SRB** (1984-2000)
  and **CERES SYN1deg** (2001 on). Every catalogue parameter was checked against the live API.
- Land outlines: **Natural Earth** 1:110m and 1:50m land (public domain).

## Run and test

```
npm ci
npm run dev        # local dev server
npm test           # vitest: statistics vs scipy / pymannkendall fixtures + property tests
npm run e2e        # Playwright (bundled headless Chromium), includes one LIVE NASA POWER test
```

Reference fixtures (Python venv, one time: `/opt/homebrew/bin/python3.11 -m venv .venv && .venv/bin/pip install -r tools/requirements.txt`,
then `npm run fixtures`, which runs `.venv/bin/python tools/make_fixtures.py`): `tools/make_fixtures.py` (Python 3.11, scipy, numpy, pymannkendall) writes
`tests/fixtures/stats_reference.json`, which the TypeScript statistics must match.

Guided-case snapshots: `.venv/bin/python tools/make_snapshots.py` saves the exact NASA POWER requests the cases use
into `public/data/snap/`, so the cases also work when the API is unreachable.

## Use of AI

AI tools were used and are disclosed here, in the app footer and in source-file headers.

- **Code and text:** written with **Claude (Anthropic)** under the direction of team Slope and Signal,
  including the statistics code, charts, visual design (layout and colours), on-screen text, the demo deck text
  and the submission drafts. Claude also ran exploratory analyses of NASA POWER data to help choose the guided cases.
  The team selected this challenge on the assistant's recommendation and approved the design. The feature set follows
  the objectives listed in the challenge statement; Claude proposed how to implement them and wrote the code and text.
  The team directed the work, checked results and made the decisions.
- **Data and numbers:** no number in the app is generated by AI. All values come from NASA POWER at run
  time (or a saved copy of the same request for the guided cases), and all statistics are computed by
  the code in `src/stats`, tested against scipy and pymannkendall.
- **Images:** no AI-generated images or video are used. Screenshots are real captures of the app.

## Deploying

Every push to `main` runs `.github/workflows/pages.yml` (tests, build, deploy). Push events can reach Actions several
minutes late, so a run first checks that its commit is still the head of `main` and skips the deploy if not; this
stops a late run from putting an older version back online. To deploy at once: `gh workflow run pages.yml`.
The live commit is shown at https://seunghyeon1004.github.io/slope-and-signal/version.txt.
